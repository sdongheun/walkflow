# WalkFlow 1차 배포 MVP

작성 기준일: 2026-03-31  
배포 대상: Android 1차 배포  
배포 목적: 한 교차로의 평일 보행자 신호 예측 기능을 사용자에게 이해하기 쉬운 형태로 제공

## 1. 1차 배포 목표

1차 배포의 목표는 "대학교 근처 1개 교차로의 평일 신호등 주기를 바탕으로, 사용자가 지금 또는 곧 언제 건널 수 있는지 직관적으로 확인할 수 있는 안드로이드 앱"을 출시하는 것이다.

이번 1차 배포에서는 전체 프로젝트의 최종 목표인 다중 교차로 지원이나 신호 반영 길찾기까지 가지 않는다.  
핵심은 이미 거의 정리된 신호등 데이터를 안정적으로 보여주고, 사용자가 실제로 보기 편한 UI로 완성해 배포하는 것이다.

## 2. 현재 전제

- 1차 배포용 신호등 데이터 정리는 약 95% 완료 상태다.
- 대상 범위는 "한 교차로"로 한정한다.
- 대상 시간 범위는 "평일" 기준으로 한정한다.
- 현재 프로젝트에는 신호 주기 계산 로직과 카운트다운 UI의 기본 형태가 이미 존재한다.
- 남은 핵심 작업은 사용자 관점의 UI 정리와 안드로이드 배포 준비다.

## 3. 1차 MVP 핵심 범위

### 포함 범위

- [x] 한 교차로의 평일 신호 주기 데이터 사용
- [x] 현재 시각 기준 다음 보행자 신호 시작 시점 계산
- [x] 보행 가능 여부 표시
- [x] 남은 대기 시간 카운트다운 표시
- [x] 예측 불가 시간대 또는 전환 구간 안내
- [ ] 사용자 입장에서 보기 쉬운 메인 화면 UI 정리
- [ ] 안드로이드에서 실제 실행 가능한 배포본 준비

### 제외 범위

- [ ] 4개 교차로 전체 지원
- [ ] 목적지 기반 길찾기
- [ ] 신호 대기 시간을 반영한 최적 경로 추천
- [ ] 건강 앱 실제 연동
- [ ] 주말 신호 패턴 지원
- [ ] 심야/예외 상황 정교화

## 4. 1차 MVP에서 사용자에게 제공해야 하는 가치

- 사용자는 현재 보고 있는 교차로에서 언제 파란불이 켜지는지 알 수 있어야 한다.
- 사용자는 지금 건널 수 있는지, 아니면 얼마나 기다려야 하는지 바로 이해할 수 있어야 한다.
- 사용자는 예측 가능한 시간대와 예측이 어려운 전환 구간을 구분해서 볼 수 있어야 한다.

## 5. 사용자 시나리오

### 시나리오 1. 바로 확인

1. 사용자가 앱을 연다.
2. 메인 화면에서 대상 교차로의 현재 상태를 본다.
3. 지금 파란불인지, 빨간불인지, 다음 파란불까지 몇 초 남았는지 확인한다.

### 시나리오 2. 전환 구간 확인

1. 사용자가 전환 시간대에 앱을 연다.
2. 앱은 정확한 예측이 어렵다는 점을 표시한다.
3. 사용자는 현재 구간이 예측 불가 시간대임을 이해한다.

## 6. 반드시 들어가야 하는 UI 요소

- 교차로 이름 또는 교차로 식별 정보
- 현재 상태 배지
  - 예: `파란불`, `다음 파란불 대기`, `예측 불가`
- 큰 숫자의 카운트다운 영역
- 현재 적용 중인 시간대 정보
- 다음 보행 가능 시각
- 예측 불가 시 안내 문구

## 7. UI 설계 방향

1차 배포 UI는 기능 확장성보다 "즉시 이해"에 집중해야 한다.

원칙:
- 첫 화면에서 핵심 정보가 바로 보여야 한다.
- 사용자가 숫자와 상태를 3초 안에 이해할 수 있어야 한다.
- 현재 상태에 따라 색상과 문구가 명확히 달라져야 한다.
- 불필요한 탐색, 설정, 경로 기능은 넣지 않는다.
- "교차로 1개 전용 앱"처럼 보여도 괜찮으니 정보 전달력을 우선한다.

## 8. 기능 요구사항

### F1. 현재 상태 표시

- 앱은 현재 시각 기준 해당 교차로의 상태를 보여줘야 한다.
- 상태는 최소 `보행 가능`, `대기`, `예측 불가` 3종으로 구분되어야 한다.

완료 기준:
- 사용자가 앱을 열자마자 현재 상태를 알 수 있다.

### F2. 카운트다운 표시

- 대기 중이면 다음 파란불까지 남은 시간을 초 단위로 보여줘야 한다.
- 보행 가능 상태면 남은 파란불 시간을 보여줄 수 있어야 한다.

완료 기준:
- 카운트다운 숫자가 안정적으로 갱신된다.

### F3. 시간대 정보 표시

- 현재 적용 중인 평일 시간대 구간을 보여줘야 한다.
- 전환 구간일 경우 예측이 어려운 이유를 안내해야 한다.

완료 기준:
- 사용자가 왜 예측 가능한지 또는 왜 예측 불가인지 이해할 수 있다.

### F4. 단일 교차로 고정 지원

- 1차 배포는 단일 교차로 기준으로 동작해도 된다.
- 교차로 선택 기능은 필수가 아니다.

완료 기준:
- 앱이 한 교차로 데이터를 기준으로 일관되게 동작한다.

### F5. Android 배포 준비

- 안드로이드에서 앱이 실행 가능해야 한다.
- 빌드 및 설치 과정에서 치명적 오류가 없어야 한다.
- 기본 앱 아이콘, 앱 이름, 권한 문구, 배포용 설정이 정리되어야 한다.

완료 기준:
- 내부 테스트 또는 실제 APK/AAB 배포가 가능한 상태

## 9. 1차 배포 완료 조건

아래 조건을 모두 충족하면 1차 MVP 배포 가능 상태로 본다.

- [ ] 한 교차로의 평일 신호 데이터가 앱 로직에 연결되어 있다.
- [ ] 현재 상태, 대기 시간, 다음 보행 가능 시각이 화면에 표시된다.
- [ ] 전환 구간에서는 예측 불가 안내가 정상 표시된다.
- [ ] UI가 일반 사용자가 봤을 때 직관적이다.
- [ ] Android 실기기 또는 에뮬레이터에서 정상 동작한다.
- [ ] 배포용 빌드가 가능하다.

## 10. 1차 배포 후 과제로 넘길 항목

- 4개 교차로 확장
- 교차로 선택 또는 지도 기반 선택
- 목적지 입력 및 길찾기
- 신호 대기 시간을 반영한 경로 추천
- 실제 건강 앱 연동
- 주말 및 추가 시간대 지원

## 11. 한 줄 정의

WalkFlow 1차 배포 MVP는 "한 교차로의 평일 보행 신호 타이밍을 사용자가 가장 쉽게 이해할 수 있게 보여주는 안드로이드 앱"이다.
