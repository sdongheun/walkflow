# WalkFlow 우선순위 정리

기준 문서: `project-goals.md`, `mvp.md`  
작성 기준일: 2026-03-31  
판단 기준: 사용자 목표 달성 기여도 + 현재 코드 공백

## 1. 우선순위 원칙

우선순위는 아래 순서로 둔다.

1. 목표 1 달성에 직접 필요한 기능
2. 목표 2 구현의 선행조건이 되는 데이터/경로 구조
3. 사용자 경험 개선 요소
4. 실제 배포 품질을 위한 연동 고도화

## 2. 현재 우선순위

### P0. 목표 1 완성에 필요한 핵심 항목

- [ ] 4개 교차로 데이터 모델 확정
- [ ] 교차로별 좌표, 이름, 횡단보도 타입, 시간대별 신호 주기 정리
- [ ] 현재 카운트다운 로직을 "교차로 1개 고정"에서 "선택된 교차로 기준"으로 전환
- [ ] 지도에서 4개 교차로를 표시하고 선택 가능하게 구성
- [ ] 사용자가 각 교차로의 다음 보행 신호 시점을 확인할 수 있도록 UI 정리

우선순위 이유:
- 이 단계가 끝나야 목표 1이 실제로 달성된다.
- 현재 프로젝트의 핵심 차별점은 실측 교차로 데이터이며, 이 자산이 아직 앱 구조에 완전히 연결되지 않았다.

현재 상태:
- 부분 준비됨: 신호 예측 엔진
- 미구현: 다중 교차로 데이터 연결, 선택 흐름, 교차로별 표시

### P1. 목표 2 착수를 위한 선행 항목

- [ ] 실제 보행 경로 API 또는 경로 계산 방식 확정
- [ ] 경로를 교차로 단위로 분해할 수 있는 구조 마련
- [ ] 경로 중 측정 대상 교차로 포함 여부 판정
- [ ] 사용자 현재 위치에서 교차로까지 도달 예상 시간 계산
- [ ] 보행 속도 값을 경로 시간 계산에 반영

우선순위 이유:
- 목표 2는 길찾기처럼 보이지만, 본질은 "경로 + 신호 대기 시간" 통합 계산이다.
- 이 계산을 하려면 먼저 실제 경로 데이터가 필요하다.

현재 상태:
- 부분 준비됨: 현재 위치 조회, 목적지 좌표 확보, 보행 속도 상태값
- 미구현: 실제 경로 계산 및 신호 반영 로직

### P2. 목표 2 완성 항목

- [ ] 후보 경로별 총 소요 시간 계산
- [ ] 신호 대기 시간을 포함한 경로 비교
- [ ] 최적 경로 추천 문구 및 시각화
- [ ] "왜 이 경로가 더 빠른지" 설명 UI 추가

우선순위 이유:
- 사용자가 제품 가치를 체감하는 구간이다.
- 하지만 P0, P1 없이 바로 구현하면 로직 신뢰도가 낮아진다.

### P3. 후속 품질 및 운영 항목

- [ ] 주말/심야/예외 시간대 신호 모델 추가
- [ ] 전환 구간 예측 정확도 개선
- [ ] 실제 건강 앱 연동 복구
- [ ] 데이터 갱신 프로세스 문서화
- [ ] 테스트 자동화 추가

## 3. 권장 실행 순서

### 1단계

- [ ] 4개 교차로 데이터 테이블 만들기
- [ ] 각 교차로를 지도 마커와 연결하기
- [ ] 선택한 교차로의 카운트다운 표시하기

완료 기준:
- 사용자가 앱에서 4개 교차로 각각의 다음 파란불을 확인할 수 있어야 한다.

### 2단계

- [ ] 현재 위치-목적지 실제 보행 경로를 가져오기
- [ ] 경로에서 측정 교차로를 매칭하기
- [ ] 각 교차로의 예상 도착 시각 계산하기

완료 기준:
- 특정 목적지 경로에 대해 "어느 교차로를 언제 건너는지" 계산 가능해야 한다.

### 3단계

- [ ] 대기 시간까지 포함한 총 이동 시간 계산
- [ ] 대안 경로 비교 및 추천
- [ ] 결과 설명 UI 추가

완료 기준:
- 앱이 단순 직선 연결이 아니라 더 빠른 도보 경로를 추천해야 한다.

## 4. 보류 또는 낮은 우선순위 항목

- [ ] 건강 앱 실연동 고도화
- [ ] 사용 기록 저장
- [ ] 개인화 추천
- [ ] 푸시 알림

판단 이유:
- 현재 제품 가치를 검증하려면 먼저 4개 교차로 예측과 신호 반영 경로 계산이 완성되어야 한다.
- 건강 앱 실연동은 유용하지만 지금 단계에서는 mock으로도 핵심 논리 검증이 가능하다.
