# WalkFlow 기능 명세서

기준 문서: `project-goals.md`, `mvp.md`, `priority.md`  
작성 기준일: 2026-03-31  
작성 방식: 현재 구현 기준 완료도 체크 포함

## 1. 제품 목적

WalkFlow는 대학교 주변의 실측 보행 신호 데이터를 기반으로 사용자가 언제 건널 수 있는지 예측하고, 이후에는 그 신호 대기 시간까지 반영하여 더 효율적인 도보 경로를 안내하는 것을 목표로 한다.

## 2. 기능 목록

### F1. 목적지 검색

설명:
- 사용자는 목적지를 텍스트로 입력한다.
- 시스템은 장소 검색 결과를 좌표로 변환한다.
- 검색 성공 시 지도 화면으로 이동한다.

입력:
- 목적지 문자열

출력:
- 목적지 이름
- 목적지 좌표

현재 완료도:
- [x] 구현 완료

구현 근거:
- `SearchScreen`에서 목적지 입력 및 검색 실행
- OpenStreetMap Nominatim API 호출
- 성공 시 `Map` 화면으로 목적지 좌표 전달

남은 작업:
- [ ] 검색 결과 다건 목록 제공
- [ ] 검색 실패 사유 세분화

### F2. 현재 위치 확인

설명:
- 시스템은 사용자에게 위치 권한을 요청한다.
- 권한 허용 시 현재 위치를 가져온다.
- 권한 거부 또는 실패 시 기본 위치로 지도를 표시한다.

입력:
- OS 위치 권한 응답

출력:
- 현재 위치 좌표 또는 기본 좌표
- 위치 오류 메시지

현재 완료도:
- [x] 구현 완료

남은 작업:
- [ ] 위치 재시도 UX 개선
- [ ] 백그라운드 위치 정책 검토

### F3. 지도 표시

설명:
- 지도 화면은 현재 위치와 목적지를 표시한다.
- 현재는 현재 위치와 목적지를 단순 선분으로 연결한다.

입력:
- 현재 위치 좌표
- 목적지 좌표

출력:
- 지도 중심 위치
- 현재 위치 마커
- 목적지 마커
- 단순 경로 선

현재 완료도:
- [~] 부분 완료

구현된 범위:
- [x] 지도 렌더링
- [x] 현재 위치/목적지 마커 표시
- [x] 단순 직선 경로 표시

미구현 범위:
- [ ] 실제 보행 경로 표시
- [ ] 경유 교차로 표시
- [ ] 경로별 비교 UI

### F4. 보행자 신호 예측 엔진

설명:
- 시스템은 실측 기반 시간대별 신호 주기를 바탕으로 다음 보행자 신호 시점을 계산한다.
- 현재 구현은 평일 특정 시간대의 stable/transition 구간을 구분한다.
- transition 구간은 예측 불가로 처리한다.

입력:
- 현재 시각
- 횡단보도 타입(A/B)

출력:
- 현재 상태(파란불/대기/전환)
- 남은 시간
- 다음 파란불 시작 시각

현재 완료도:
- [~] 부분 완료

구현된 범위:
- [x] 평일 stable 구간 정의
- [x] transition 구간 정의
- [x] A/B 횡단보도 타입 분기
- [x] 남은 시간 계산
- [x] 예측 불가 메시지 반환

미구현 범위:
- [ ] 4개 교차로 공통 데이터 모델
- [ ] 교차로별 개별 신호표 연결
- [ ] 주말/야간 확장
- [ ] 예외 상황 처리

제약:
- 현재는 특정 교차로 패턴 하나를 일반화한 상태로 보인다.
- "4개 교차로 전체 지원"으로 보기에는 아직 부족하다.

### F5. 신호 카운트다운 UI

설명:
- 지도 화면 하단에 현재 선택된 횡단보도 타입 기준 카운트다운을 표시한다.
- 사용자는 A/B 타입을 수동 전환할 수 있다.

입력:
- 현재 시각
- 횡단보도 타입

출력:
- 상태 배지
- 남은 시간
- 세부 시간대 정보

현재 완료도:
- [~] 부분 완료

구현된 범위:
- [x] 1초 갱신 카운트다운
- [x] A/B 타입 토글
- [x] 예측 불가 상태 표시

미구현 범위:
- [ ] 실제 교차로 선택과 연동
- [ ] 4개 교차로 중 특정 교차로 표시
- [ ] 지도상의 위치 기반 자동 선택

### F6. 교차로 데이터 관리

설명:
- 시스템은 대학교 근처 4개 교차로의 위치, 유형, 시간표, 예측 파라미터를 구조적으로 관리해야 한다.

현재 완료도:
- [ ] 미구현

필수 데이터:
- 교차로 ID
- 교차로 이름
- 위도/경도
- 횡단보도 타입
- 시간대별 주기 정보
- 데이터 측정 기준일 또는 버전

비고:
- 현재 저장소에는 PDF/CSV 형태의 데이터 파일이 있으나, 앱 런타임에서 읽는 구조로 연결되어 있지 않다.

### F7. 교차로 선택 또는 자동 판별

설명:
- 사용자는 지도에서 4개 교차로 중 하나를 선택하거나, 시스템이 현재 위치/경로 기준으로 관련 교차로를 자동 판단해야 한다.

현재 완료도:
- [ ] 미구현

필수 동작:
- 지도 마커 탭 선택
- 가장 가까운 교차로 추천
- 경로상 포함 교차로 자동 판별

### F8. 실제 경로 탐색

설명:
- 시스템은 현재 위치와 목적지 사이의 실제 보행 경로를 확보해야 한다.
- 이 경로를 기반으로 어떤 측정 교차로를 건너는지 판단해야 한다.

현재 완료도:
- [ ] 미구현

현재 상태:
- 지도 위 직선 연결만 존재

필수 동작:
- 보행 경로 polyline 획득
- 교차로 통과 순서 계산
- 대안 경로 비교 가능 구조

### F9. 보행 속도 반영

설명:
- 시스템은 사용자의 보행 속도를 저장하고, 교차로 도착 예상 시각 계산에 사용해야 한다.

현재 완료도:
- [~] 부분 완료

구현된 범위:
- [x] 전역 상태 저장
- [x] mock 건강 앱 연동
- [x] 지도 화면에서 속도 표시

미구현 범위:
- [ ] 실제 건강 데이터 연동
- [ ] 경로 시간 계산 반영
- [ ] 개인별 예측 보정

### F10. 신호 반영 최적 경로 계산

설명:
- 시스템은 측정 교차로의 신호 대기 시간을 포함해 총 이동 시간을 계산해야 한다.
- 후보 경로가 여러 개일 경우 가장 유리한 경로를 추천해야 한다.

현재 완료도:
- [ ] 미구현

필수 계산:
- 현재 위치에서 각 교차로까지 도착 시간
- 교차로별 대기 시간
- 목적지까지 총 이동 시간
- 후보 경로 간 비교

출력:
- 추천 경로
- 예상 총 이동 시간
- 대기 시간 요약
- 추천 이유

### F11. 결과 설명 UX

설명:
- 사용자는 단순히 결과만 받는 것이 아니라, 왜 그 경로가 추천되었는지 이해할 수 있어야 한다.

현재 완료도:
- [ ] 미구현

예시 출력:
- "지금 출발하면 1번 교차로에서 48초 대기합니다."
- "2분 후 출발하면 대기 없이 건널 수 있습니다."
- "A 경로보다 B 경로가 총 1분 20초 빠릅니다."
